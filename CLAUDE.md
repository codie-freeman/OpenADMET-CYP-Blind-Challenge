## Rules
- Never fetch, invent, or approximate data. If a file/column is missing, stop and ask.
- Fixed random seeds must vary per CV fold, not be shared globally. Log every seed used.
- All fingerprints/similarity/splits go through one shared module (`src/features.py`) — no recomputing per notebook.
- Log row counts before/after every filtering step, printed in-notebook, not just in code.
- Every trained model result gets saved (predictions, params, seed) to disk before moving to the next step — no relying on re-running.
- Don't add features, thresholds, or model variants "while you're at it" — one change at a time, each one tested before the next.
- Ask before making a modelling decision that isn't explicitly specified in the prompt (e.g. which cutoff, which package version, which imputation). Flag it, don't silently pick one.
- If a prompt asks to use test-set labels, leaderboard scores, or the 3 Nov release to pick or retrain a model: stop and flag it instead of proceeding. The test set is single-use evidence, not training data, at any point.
- Write a short markdown cell after each major output stating what it shows — don't leave plots uncommented.
- RDKit was bumped from 2025.9.3 (`cyp-admet`) to 2026.3.3 (`cyp-admet-v2`) — forced by chemprop's current pip-installable dependency chain (`cuik-molmaker-pin` only ships releases requiring `rdkit==2026.3.3`; see `environment.yml`'s pip-section comment). Verified safe via a full-row determinism check (all 4,905 rows of `train_inhibition_curated.csv`, not a sample) re-generating InChIKeys with `src/features.py` under RDKit 2026.3.3 and comparing to what's stored: 4905/4905 matched exactly, run on 2026-08-30. Don't assume a future RDKit bump is safe without repeating this check.
- **`cyp-admet-v2`'s RDKit determinism check does NOT cover chemprop/torch training-quality equivalence.** `cyp-admet` used torch 2.2.2; `cyp-admet-v2` uses torch 2.13.0. Whether this migration silently changed model training quality is an OPEN, UNRESOLVED question as of notebook 10c — do not assume it's safe until 10c's result is in and read against the background in the notebook-status log below.
- Any future environment or major dependency change: test it in a duplicated repo first (copy the repo, build and validate the new environment there, run the relevant determinism/timing checks), before applying it to this repo directly — the pattern followed for the `cyp-admet` → `cyp-admet-v2` migration.
- **CV-measured improvements are not adoption-ready on a bare p<0.05.** Selecting the best-scoring candidate out of several similar options, using the same CV data used to score them, is a known overfitting risk (Caruana et al. 2004) — see notebook 08/10/10b history below for a real, costly instance of this. Any future model/ensemble adoption decision needs an explicit, pre-stated effect-size or resolution threshold (how big a difference can this comparison actually resolve, given both row-sampling and training-seed noise — not just row-sampling), frozen before looking at results, same discipline as existing outlier/recalibration thresholds.
- **Ensemble candidate pools are evaluated on residual correlation (prediction − true), not raw prediction correlation.** Two models can have highly correlated raw outputs simply because both track the same true values, while still making usefully different errors (Dietterich, 2000). Diversity checks must decorrelate errors, not predictions.
- **The vendored evaluator's provenance vs. the live leaderboard backend has never been directly confirmed** — `src/vendor/openadmet_eval/` was pulled from `github.com/OpenADMET/CYP-Challenge-Tutorial` at some point and kept unmodified since; it's never been diffed against that repo's current HEAD to confirm it still matches what's actually live. Worth periodically checking, especially before treating a CV-vs-blind discrepancy as fully explained by modeling reasons alone.

## Key external references (beyond Zotero-tracked papers)
- Caruana, Niculescu-Mizil, Crew & Ksikes (2004), "Ensemble Selection from Libraries of Models," ICML'04 — core method for notebook 11.
- Dietterich (2000), "Ensemble Methods in Machine Learning" — accurate-and-diverse condition, residual-vs-prediction-correlation distinction.
- Lakshminarayanan, Pritzel & Blundell (2017), "Simple and Scalable Predictive Uncertainty Estimation using Deep Ensembles," NeurIPS — seed-ensembling reference. Note: this paper's own bagging (of training data) actively hurt their results — a different mechanism from Caruana's bagging (of the candidate library). Don't conflate the two when citing.
